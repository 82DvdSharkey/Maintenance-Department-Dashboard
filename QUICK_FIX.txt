# Quick Reference: Daniel Kragel Unmapped Names Fix

## The Issue
✗ 3,514 Fiix work orders for "Dan Kragel" are **NOT** being attributed to technician ID 14

## The Root Cause
- Fiix data contains: `completed_by="Dan Kragel"` → normalizes to key `"dan kragel"`
- Technician record exists: ID=14, name="Dan Kragel", but **fiix_name=NULL**
- No Fiix source alias exists to map "dan kragel" → technician_id=14
- **Result:** 3,514 work orders cannot be matched to the technician

## The Fix
Run this SQL command to add the missing Fiix alias:

```sql
INSERT INTO technician_aliases (source, alias, alias_key, technician_id)
VALUES ('fiix', 'Dan Kragel', 'dan kragel', 14);
```

## Why This Happened
The application resolves Fiix work orders using an alias index built from:
1. Technician names
2. Source-specific name fields (fiix_name, dayforce_name, ignition_name)
3. Technician aliases table entries

Dan Kragel's fiix_name was never populated, and no Fiix source alias was created. Without either of these, the 3,514 work orders from Fiix with "Dan Kragel" as completed_by cannot be matched to his technician record.
